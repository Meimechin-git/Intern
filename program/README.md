# 解析プログラム

　本フォルダには、Tidy Towers の最大最小手数を調べるために作成した解析プログラムを格納している。

　ここでは、すべての盤面を幅優先探索（BFS）によって探索し、それぞれの盤面を解くために必要な最小手数を求めることで、最大最小手数を調べている。

## ファイル構成

```text
program/
├── README.md
├── cube_bfs.py
└── cube_updated.py
```

### `cube_bfs.py`

　最大最小手数を求めるために最初に作成したプログラムである。

差分列を状態として扱い、解状態

```text
(0, 0, ..., 0)
```

から幅優先探索を行う。

　探索によって各状態までの最小手数を求め、すべての状態を探索した後、その中で最も大きい手数を最大最小手数として出力する。

また、最大最小手数となる盤面も出力を行う。

### `cube_updated.py`

　`cube_bfs.py` をもとに、探索速度と扱える問題の大きさを改善したプログラムである。

主な変更点は以下の通りだ。

* 状態をタプルではなく整数としてエンコード
* 状態の深さを `dict` ではなく `bytearray` で管理
* 操作を「1つの差分だけを変化させる操作」と「2つの差分を変化させる操作」に分離
* 盤面表示にルックアップテーブルを使用
* 探索済み状態の管理方法を変更することでメモリ使用量を削減

　これらの変更により、基本的な探索方法は維持したまま、より多くの状態を扱えるようにした。

## 解析方法

### 1. 差分列による状態表現

　各段の向きを $c_i$ とし、隣り合う段の差を

$$
\delta_i=c_{i+1}-c_i\pmod{s}
$$

と定義する。

これにより、$n$ 段のタワーは

$$
(\delta_1,\delta_2,\ldots,\delta_{n-1})
$$

という $n-1$ 個の値からなる差分列として表現できる。

　各差分は $0,\ldots,s-1$ の $s$ 通りの値を取るため、異なる差分状態は

$$
s^{n-1}
$$

通り存在する。

解状態は、すべての段の向きが等しい状態なので、

$$
(0,0,\ldots,0)
$$

となる。

### 2. 幅優先探索

　解状態から、可能なすべての回転操作を1手ずつ適用して探索する。

　幅優先探索では、距離の近い状態から順番に探索するため、ある状態を最初に訪れたときの探索深さが、その状態を解状態から作るための最小手数になる。

　そのため、すべての状態について最小手数を求めた後、

$$
\max_X d(X)
$$

を計算することで、最大最小手数を求めることができる。これについて、`cube_bfs.py` では、探索した状態とその最小手数を辞書で管理している。

## `cube_bfs.py` から `cube_updated.py` への改善

### 状態の整数化

初期版では、差分列を

```python
(0, 1, 2, 3)
```

のようなタプルとして扱い、辞書を用いて探索済み状態を管理している。

改善版では、差分列を $s$ 進数として1つの整数に変換する。

例えば、差分列

$$
(\delta_1,\delta_2,\ldots,\delta_{n-1})
$$

を整数として表現することで、状態を1つの整数として管理できる。

改善版では、このエンコードに使用する $s^i$ をあらかじめ計算しておき、状態の更新を整数の加減算によって行っている。

### `bytearray` による深さ管理

　改善版では、すべての状態について「未訪問」または「何手で到達したか」を `bytearray` によって管理している。

```python
depth_arr = bytearray([0xff] * total)
```

として、`0xff` を未訪問状態として利用している。これにより、辞書を用いて状態を管理する初期版と比較して、状態管理に必要なメモリを削減した。

### 操作の分類

　改善版では、回転操作を

* `single_ops`：1つの差分だけを変化させる操作(端点操作)
* `double_ops`：2つの差分を変化させる操作(非端点操作)

に分けた。

　これは、タワーの端を含む操作では1つの差分だけが変化し、端を含まない操作では2つの差分が変化するという、差分列上の操作の性質に対応している。

## 実行方法

　Python 3 がインストールされている環境で実行できる。

### 初期版

```bash
python cube_bfs.py
```

実行すると、

```text
側面の数を2~7の自然数で入力してください:
```

と表示されるため、正多角柱の側面数を入力します。

続いて、

```text
タワーの段数を2以上の自然数で入力してください:
```

と表示されるため、タワーの段数を入力する。

### 改善版

```bash
python cube_updated.py
```

改善版では側面数として3～10を入力できる。

---

## 出力

プログラムでは主に以下の情報を出力する。

* 探索時間
* 各最小手数の盤面数
* 最大最小手数
* 最大最小手数が必要となる盤面

例えば、最大最小手数が $d$ 手であった場合、

```text
最大最小手数: d 手
```

のように表示される。

また、探索した状態数が

$$
s^{n-1}
$$

と一致しているかを確認し、すべての状態を探索できた場合には

```text
All elements are explored
```

と表示する。

## 実行時間の比較

　側面の数を $s=7$ に固定し、タワーの段数 $n$ を変化させて、`cube_bfs.py` と `cube_updated.py` の2つのプログラムで全状態を探索した。

　差分列で表現した状態数は $7^{n-1}$ である。BFSによって各状態から完成状態までの最小手数を求め、その中で最も大きい値を最大最小手数とした。

　`cube_bfs.py` と `cube_updated.py` の実行時間を比較すると、すべての $n$ において `cube_updated.py` の方が短い時間で全状態を探索できた。

特に $n=8$ では、

$131.66$ 秒から $31.551$ 秒と、約4.2倍高速になった。

また、$n=9$ では、

$1109.3$ 秒から $312.46$ 秒と、約3.6倍高速になった。

　このように、段数 $n$ が大きくなるにつれて状態数 $7^{n-1}$ が急激に増加するため、プログラムの実装方法による実行時間の差も大きくなった。

　`cube_updated.py` では、状態をタプルではなく整数として表現し、探索済み状態の深さを bytearray で管理するなどの改良を行っている。このことにより、同じ BFS による全状態探索であっても、より大きな状態空間を効率的に探索できるようになった。

　以上の実験から、最大最小手数について理論式との一致を確認するとともに、探索プログラムの改良によって計算時間を短縮できることを確認できた。

　ここで得られた最大最小手数にたいして、ルートディレクトリの `README.md` で、理論的な証明と比較を行った。

本インターンシップでは、

$$
\boxed{
D(n,s) = n-\left\lceil\frac ns\right\rceil = \left\lfloor\frac{n(s-1)}s\right\rfloor
}
$$

という式を予想し、計算機による全探索によってその成立を確認するとともに、理論的な証明を行った。

したがって、本フォルダのプログラムは主に以下の目的で使用した。

1. 最大最小手数の予想
2. 小規模な問題における予想式の検証
3. 最大最小手数となる盤面の確認
4. 理論的証明との比較

理論的な証明については、ルートディレクトリの `README.md` に記している。
